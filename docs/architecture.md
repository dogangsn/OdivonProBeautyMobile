# Mobile architecture

The app is React Native on Expo (SDK 58) with TypeScript. `src/app` holds Expo Router routes: the root layout provides TanStack Query and safe-area context, starts the session listener and uses `Stack.Protected` guards so signed-out users only reach `sign-in` and signed-in users only reach the role shell. `src/app/(tabs)` builds the customer, specialist or manager bottom navigation from the verified role (`src/core/navigation.ts`). `src/core` contains typed models, the Zustand session store, the typed MainApi client (`api.ts`), the lazily loaded React Native Firebase gateway (`auth.ts`) and query hooks. `src/components` holds shared UI and `src/theme` the light/dark tokens.

Native `android/` and `ios/` folders are generated by `expo prebuild` and are not committed. Firebase is only wired in when the build runs with `ENABLE_FIREBASE=true` and a native config file is present.

Firebase Authentication supplies ID tokens and Firebase Cloud Messaging handles push registration. `MainApiBeautyRepository` sends bearer tokens only to `/api/v1/beauty`. Firestore and Storage are never called by mobile code. Photos and consent media use future signed MainApi upload commands.

The customer shell covers OTP entry, appointments, reschedule/cancel contracts, packages and remaining sessions, loyalty, notification preferences and KVKK. The staff shell covers daily appointments, check-in, session notes/photos, authorized customer history, KPI summaries and notifications. Health and finance payloads use memory only and are not written to device cache.

External adapters and Firebase project files are intentionally absent. The default build exposes no business data and keeps authentication disabled; enabling Firebase requires environment-specific configuration supplied outside source control.
